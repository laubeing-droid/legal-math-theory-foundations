# 法律数学理论基础：七步路线

日期：2026-11-13。性质：研究与施工路线，不是已完成成果清单。每一步的实际进度以任务和对应证据为准。

## 1. 法理学统稿＋中国法律运行理论

### 1A 法理学统稿

接收并阅读 AutoClaw、Kimi 的完整稿件和 Gemini 的法源、参考资料核查。分别保存其版本与来源，辨认共同结论、真正分歧、证据不足及需要补充的部分，再形成统稿。未读取的稿件不写成已经合并；模型说“已核”不自动继承为核实结论。

先明确法理学框架的组成，再圈定适合形式化的对象、关系、条件、程序、论证结构和可观察现象。逐项回答：为什么可以形式化、准备采用什么方法、保留什么差异、会失去什么、哪些判断不能被计算代替。法律逻辑学、计量法学等方法按问题进入，不为了套公式而裁剪法律。

中港美比较只在这一层检验概念与边界。涉及美国时须按题目选择联邦或具体州，不能将某州规则泛化为全美。

### 1B 中国法律运行理论

可与 1A 并行准备，但二者必须互相核对。内容不是机构简介，也不是只画诉讼链。至少安排以下问题：

- 规范与权威：国家法律、党内法规、政策及其他文件如何形成、适用、监督和变化；各自效力与用途如何区分。
- 社会关系与常态运行：主体、身份、权利义务、权限责任，以及交易、履行、登记、许可和组织活动。
- 党内监督与政法工作：纪委、政法委员会的地位、职责、程序和衔接；分别论证党内规则、国家法律与实际工作机制。
- 国家机关与法律职业：人大及其常委会、行政机关、监察机关、公安与国家安全机关、检察院、法院、司法行政机关，以及律师、法律援助、公证、鉴定、仲裁、调解等参与者。
- 程序与层级：民事一审、二审、再审与非讼程序；刑事侦查、审查起诉、审判、救济与执行；行政处罚、许可、强制、复议与诉讼；监察调查、处置及其与其他程序的衔接。党内监督程序也须有位置，不能由监察程序代替。
- 结果与实现：决定、裁判、合意、履行、执行、监督、救济、纠错及法律变化。
- 实际运行与经验研究：通道选择、资源和知情、组织激励、数据覆盖与样本选择。实际影响不能直接充当法律效力。

上述内容是必须研究的覆盖范围，不是已经核清的制度命题。具体权限、程序与后果须回到适用法源。

**交付：** 法理学统稿、中国法律运行论证、形式化候选及理由、分歧与待核清单。候选优先级不得被误读为永久删去其余目标。

## 2. 中国法律运行总图＋资产盘点

总图把理论表达为主体、权限、条件、行为、程序、结果和连接关系。常态、争议、公权运行与变化应能互相连接，不把所有案件画成一条必经链。时间节点、第三方独立地位、监督与救济也须保留。

图中发现遗漏，经过法律论证回补第一步；不能因为现有代码没有某节点，就删掉制度，也不能因为代码有某功能就认定法律允许。

盘点本地和远端数学仓、JC、律师工作流、工作台、法律资料、数据集与纸面设计。每项记录版本、位置、自称功能、实际观察、适用范围和证据。区分：

- 已在明确范围内验证可用；
- 初步可复用、待核；
- 已有未接；
- 存在冲突；
- 在已查范围内未发现。

“可读”“法律对应已核”“数学已证”“程序已测”“实际已接通”分别说明，不互相替代。静态读取不能声称新增测试通过；旧报告要绑定原版本，不移植为当前结论。盘点范围不完整时不能断言全库缺失。

**交付：** 运行总图、可追溯资产清单、冲突与缺口、回补意见。总图中的制度位置与代码对应位置分开记。

## 3. 法律工作流程规格＋库存对应

把总图中的行为写清楚：谁做、凭什么、输入是什么、何时发生什么结果、结果交给谁、失败或例外怎样处理。

例如，文件写好、提交成功、机关收到、正式受理，不能压成同一个事件；各类机关的移送与接收也要分别说明条件。履行、登记、许可等常态流程与争议流程同样需要规格。

本步限静态核对：读文件、查接口声明、检索、对照法律规格。**不运行程序、不编译、不跑测试、不改代码。** 对应表写“可能覆盖／已核到何种对应／未接／冲突”，不因文件存在就宣称实现了法律效果。

**交付：** 流程规格与库存对应，列出待数学处理和待工程处理的问题。缺资产不降规格；发现理论问题须返回第一步论证。

## 4. 统一数学理论与补正

根据法律理论和规格，复用已有对象、算子、定义与证明，修正错误、补足缺项。统一是研究目标；阶段性结论必须写明其覆盖范围，不能用接口接通或测试通过代替法律机制之间的数学推导。

每项给出法律对应、前提、推导目标、已证明结论、未证明部分与反例边界。必要时回修理论或规格，但不能为施工便利改写法律含义。部门法实例与反例在此检验通用对象。

规范推理与概率、行为研究分清对象和证据。经验模型须说明目标、数据、选择机制、评价方法和适用范围；预测不能自行产生法律规则或现实裁判。某类统计材料依法如何进入个案判断，需要具体规则和程序，不作无条件结论。

JC 的 RSI 在这一阶段确定需要数学论证的对象与条件，不把所有工程升级扩成通用 RSI 理论。已有训练代码不等于真实数据上的有效改进，具体对象参见边界文档。

**交付：** 数学仓的复用与补正方案、定义和证明任务、经验模型与 JC RSI 的待验证问题。数学证明与工程运行验证分别记账；当前建仓不解除其他仓的冻结或授权限制。

## 5. 中国部门法特化

民事、刑事、行政、监察等领域及相应程序、执行规则，在通用理论上系统展开。后续按任务细化具体部门法，不把四个类别当成穷尽目录。

每个包说明：特有前提、主体与程序、要件与后果、例外、通用模型的复用部分和需要补正的地方，以及如何对应第三步规格和第六步实现。遇到通用理论确实容纳不了的反例，应回到理论与数学层处理，不能暗中另造不相容体系。

部门法实例从第一步就可参与检验；第五步是系统特化，不是第一次接触部门法。不建设香港或美国法域包。

**交付：** 部门法论证、专门规则与程序规格、挂接说明、反例和待核项。

## 6. 法律工程实现与接入

在相应实施任务获授权后，把经核对的理论、数学、部门法规则与现有资产落实为程序和工作流程。正式库存接线、运行验证及端到端接入在这里展开。

先复用已有资产。Legal Harness 将并入未来法律工作台，不预设另建独立产品或 RSI 服务。工作台承载办案操作、数据与结果反馈；JC 承接其经核实的计算、推理和模型能力。具体部署与接口依盘点和实施方案决定，不从仓库名推断。

检查输入输出、权限、数据状态、失败处理、来源版本、更新与日志。程序应满足法律与数学规格，而不只是“跑起来”。软件内部恢复与现实法律决定的撤销不能混淆。案件数据按实际授权和保密要求处理。

**交付：** 接入实现、运行与符合性验证结果、未接通或失败清单。没有运行的检查仍标未运行。

## 7. 整体验收

法律依据与适用、数学推导、程序实现、实际工作流程分别检查，再做联验：

| 方面 | 要核对什么 |
|---|---|
| 法律 | 原始法源、版本、适用范围及解释论证；存在争议时保留分歧 |
| 数学 | 在明确前提下证明了什么，未证明和不可能性结论是什么 |
| 程序 | 真实实现是否符合规格，包括异常、重复、失败和权限边界 |
| 工作流 | 从任务入口到结果、救济与实现的实际衔接，含非理想路径 |
| 经验模型与 JC RSI | 数据、评价、校准或行为预测的有效性，以及改进是否可复现 |

不把官方原文“查到了”直接当作全部法律论证正确；不把程序测试当作数学证明；不把单案跑通当作全系统可靠。任务达到其明确完成条件才关闭。

**交付：** 分项验收结论、对应版本与证据、仍未完成的事项。不得用一个笼统的 PASS 遮住不同层次的状态。

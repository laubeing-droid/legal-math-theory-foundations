# Agent 使用说明

本仓管理法律理论研究及其与数学、工程的衔接。先读 README、七步路线和已确认边界，再接任务。不要从聊天片段或旧稿自称的“已裁决”直接推定最新指令。

## 1. 先找任务，不重复开工

先查仓库 Issues 和配套 Projects。沿用已有任务；一项要求可以涉及多个文件，不按每个文件拆几十张卡。需要跨仓工作时，在本仓任务里链接目标资产与对应任务，不复制另一套理论或状态。

看板四列为“待做／在做／待检查／完成”。Issue 保存要求与证据，看板保存进度。没有看板权限时，在 Issue 写明当前进度和“Projects 未同步”，不要伪造看板或另建状态表。看板卡片不是自动开工授权，执行仍限于用户交办范围。

## 2. 每个任务写清这些事

- 要解决的问题与预期成果；
- 范围、涉及仓库和文档；
- 执行者与当前阻塞；
- 输入材料及其版本、哪些还没收到；
- 完成条件；
- 实际修改、提交链接与检查证据；
- 没有完成或仍不确定的部分。

提交方案、研究稿、核查报告以日期前缀命名。勿用“完成”“终版”等名称替代检查结论。

## 3. 做研究时保留证据身份

区分原始法源、学术论证、用户决定、模型提案和经验数据。查法律命题时回到适用的正式文本，记录版本和具体位置；原文存在不等于解释争议消失。参考资料可以支撑论证，不能编造引用或把经验判断写成法条。

接收 AutoClaw、Kimi 和 Gemini 材料时逐件记录来源与版本。保持原稿和统稿的区分；未经阅读不能宣称合并，无法取回的内容标未收到，不凭记忆补成原文。

中国法律运行总图与理论互相校正。制度有缺口要经法律论证再回补，不能以现有软件表达不了为由删除制度，也不能以现有代码实现了为由承认法律效果。

## 4. 盘点与运行不能混报

第三步仅静态核对：读文件、查声明、检索、比对。不执行项目程序，不编译，不跑测试，不改代码。记录已读路径、提交版本与核查范围。

资产状态要精确：文件可读、初步可复用、法律对应已核、数学已证、程序已测和跨仓已接通分别说明。没搜到只能写“在已查范围内未发现”。文档承诺、测试源码与测试运行结果是三种证据。

如果必须读取用户电脑文件，按用户规定使用廉价模型和低推理档位；不能借盘点改动其磁盘。当前理论仓建设不解除其他仓的冻结。

## 5. 修改文档要同步受影响处

编辑前读取现有文件与最新提交，检查他人并行工作。不要覆盖或丢弃别人的修改。法律含义、范围或阶段顺序有变化，检查：

1. 对应正文是否更新；
2. README 与相关导航是否仍准确；
3. 已确认边界是否受影响；
4. 关联 Issue 的完成条件和看板状态是否需要调整。

跨文档引用尽量链接权威正文，不在多处复制易变结论。无需增加自动化服务来维持简单链接。

## 6. 提交和验收

只提交任务授权范围内的文件。禁止把私人案件材料、凭据、原始私人聊天或无权公开的内容放入仓库。私有仓也不是任意上传资料的许可。

交付前检查文本、链接、命名、范围和状态表述。理论文档初始化不用伪造 CI、Lean 或程序测试结果。分主题提交，回读远端确认真实提交已生效后再报告。

完成任务要给出实际产出与检查证据，先移到“待检查”；符合完成条件再关闭 Issue、移到“完成”。有未核法源、未收稿件或未运行验证时，将其作为明确的后续任务或阻塞，不能用笼统 PASS 掩盖。

## 7. JC 与工作台的边界

RSI 本轮限定 JC 的具体改进对象。Harness 将并入工作台，其流程和工具升级按工程任务处理，不扩大为全系统通用 RSI 数学。工作台可为 JC 提供数据与操作入口，但数据流接通不等于训练有效，也不等于产生法律效力。

发现已有训练、拟合、采纳和接口资产时先复用；根据实际入口核查权限与验证路径，不能只读一份治理文档就断言所有入口都执行了同一套检查。

## 8. 多 Agent 分工与交接

按[工作日志说明](../工作日志/README.md)执行。每项任务必须有负责人、明确范围、输入版本、预期产物和阻碍记录。计划人选不是已派单，已发送不是已收到。Grok 当前尚未通过应用授权，不得写成已派单或已执行。

执行者按批次说明覆盖范围和未读部分；各自交独立版本到中转区，不直接覆盖其他 Agent 的稿件。两个任务碰到同一文件或结论时，先把冲突和各自基线报总协调，由指定负责人合并；其他人保留原稿，不抢写。

任务详情和证据放对应 Issue，卡片是唯一任务状态源。日总日志只追加跨任务变化、阻碍与交接。收件、审查、采纳分别记录。今晚不运行代码，不安装多 Agent SDK，不新增调度服务；先用已有看板、Issue、文档和中转区完成协作。

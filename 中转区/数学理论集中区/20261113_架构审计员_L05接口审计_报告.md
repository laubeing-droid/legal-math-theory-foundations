## 二、实质发现（先给结论）

1. **交接四态已在统稿中写清，且不能压成一个“提交成功”。** 统稿候选稿写明：律师已经写好起诉状、材料已经上传、法院已经收到材料、案件已经受理，是不同状态；软件记录上传成功，并不证明法院已经受理。规格层再次要求：律师草拟完成、发送完成、法院收件和正式受理必须分别表示。
2. **“受理”在内地稿里不是单一制度事件。** 同一词出现在行政许可、行政复议、公证、信访、破产和诉讼立案等不同程序中，条件、权限和下游各不相同。接口若只用一个 `accepted`，会把这些法律意思折掉。
3. **预测与规范必须分栏，已有明确禁止升级的命题。** 法理学统稿要求分析、预测、行动、决定分栏；研究设计命题八为“预测提高不蕴含规范应然改变”；RSI 稿禁止因预测更准而改写规范、证明标准、确定性内核或裁判记录。这是规范接口约束，不是已经在 JC 或数学仓中核过的实现。
4. **八座桥和十项命题是理论候选名，不是已完成映射。** 研究设计第十三章写明“只提出候选研究，不表示数学仓已经完成”，并要求沿用这些桥名。本轮只核对到数学仓存在可检索的同名或近名路径，未打开定义，因此对应关系一律待核。
5. **数学仓与候选 JC 仓均可读，但入口对应和语义对应都还没打开。** 数学仓 README 指向 `docs/UNIFIED_THEORY.md` 与 ULM01–ULM16 Lean 文件，并声明其发布快照主体是更早的提交 `013aadbf`，且“并不为此后提交背书”。候选 JC 仓可读取，但四稿未点名该地址；数学仓内另有大量 `JurisLean` 模块。三者如何对接，本轮未核。

# 工作日志怎么写

看板回答“任务走到哪一步”，工作日志回答“谁在什么时候做了什么、读了哪个版本、留下什么、下一位怎么接”。十几个 Agent 可以并行，但不能只靠移动卡片交接。

任务详情和检查证据写在对应 Issue；[日总日志](20261113_工作总日志.md)只追加重要变化、阻碍和交接，不另建一套任务状态。任务状态仍以 [Projects 看板](https://github.com/users/laubeing-droid/projects/2) 为准。

## 每次交接写这九项

- 北京时间：实际记录时刻；事件发生时间不同则另注明。
- 任务与看板卡：Issue 链接、看板卡链接；尚未对应写“待关联”，不要编编号。
- 执行者：实际执行者；计划人选另写，不当作已经接单。
- 基线：仓库、分支、commit；本地材料另记电脑和相对目录。没读到写未确认。
- 已做：具体动作和已读范围；收到报告与亲自核验分开。
- 成果链接：文件、提交或核查证据；没有就写无。
- 待办：下一步及接手人；尚未确定则明说。
- 阻碍：缺件、权限、版本冲突或其他问题；没有核实不猜原因。
- 交接：交给谁、交什么、是否收到确认。

无需为每个 Agent 再建一套日报。执行者在 Issue 留任务记录，总协调把跨任务变化和重要交接追加到当天总日志。派单、开始、收件、核查、阻碍与移交都要说清；创建文件不等于任务完成。

## 并行和纠错

日总日志以追加为主。写入前重新读取最新文件，按当前版本提交，避免覆盖别人的追加。发现错误，追加更正并指向旧记录；涉及敏感信息须立即报告并按授权处理，不以“保留历史”为由继续扩散。

日志不收私人案件原文、凭据、原始聊天或无关个人信息。不得把目录清单当成文件已读，不得把测试源码当成运行通过。第三步仍仅静态阅读和比对，不运行、不编译、不测试、不改代码。

新建每日总日志使用 `YYYYMMDD_工作总日志.md`；单项交付继续按排班规定的五段命名。这里的 README 只作固定入口。
